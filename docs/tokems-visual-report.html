Open Source System Report · 2026.08.01

一套大会运营系统， 贯通发布、交易与现场

TokEMS 是开源、自托管的一体化大会运营平台。它将大会官网、报名、票务、订单、发票、通知和现场签到收拢到统一业务模型，并通过发布快照、事务 Outbox、库存锁与幂等控制维持关键流程的一致性。

v0.1.0 Public Preview Self-hosted AGPL-3.0-only TypeScript Monorepo Chinese-first · Global roadmap

Executive judgment

适合有完整运营链路和数据主权要求的大会团队

当前版本已经形成可运行的业务骨架和较完整的工程边界。面向生产部署时，团队需要继续建设真实支付与消息集成、可观测性、容量验证、备份恢复和多语言体验。

01

项目定位与价值主张

TokEMS 面向大会组织方、运营团队和活动技术服务商，覆盖活动生命周期中的内容、交易、履约和治理。统一数据模型让跨团队协作拥有稳定的业务事实。

A

完整运营闭环

公开官网承接流量，报名与票务完成转化，订单和发票处理交易，通知与签到完成履约，审计记录支撑复盘。

B

业务一致性优先

库存、支付回调、候补释放、电子票、离线签到都配置了锁、幂等、哈希或唯一约束，降低重复执行和状态漂移。

C

自托管与可扩展

Docker Compose 提供标准运行拓扑，模块化单体 API 便于早期交付，共享包和集成层为区域服务商及二次开发留出边界。

析
核心判断

项目当前最有辨识度的能力集中在发布快照、交易一致性、候补履约、离线签到和多组织治理。这五类能力共同定义了“大会运营基础设施”的产品位置。

02

适用场景与选型边界

系统适配度随着活动链路复杂度、数据控制要求和现场运营压力提升。以下判断结合当前代码能力和公开版本边界。

Primary fit

中大型行业大会

官网、报名、付费票、通知、现场签到和发票集中协作，适合拥有内容、运营、财务及现场分工的团队。

Multi-event

多活动组织方

多组织隔离、事件级权限和模板发布能力支持持续办会，能够沉淀跨活动复用的运营资产。

Delivery

活动技术服务商

模块化业务边界、共享契约和自托管部署便于定制交付，适合连接区域支付、短信、邮件和对象存储。

Commerce

付费票与开票

库存预占、订单超时、支付回调、退款与发票生命周期提供完整底座，适合有交易核对需求的活动。

On-site

高峰签到现场

设备令牌、二维码核验、重复签到阻断和离线批量同步覆盖网络波动及多入口并发场景。

Sovereignty

数据主权部署

本地数据库、对象存储和内部网关可部署在自有环境，适合具有审计、合规或专有网络要求的团队。

03

技术原理与关键流程

系统采用模块化单体 API 与独立 Worker。同步请求负责确定业务事实，事务 Outbox 将后续任务可靠交给队列，前台发布内容通过不可变快照读取。

端到端事务流

SYNC提交报名Zod 校验
LOCK预占库存15 分钟窗口
ORDER创建订单幂等键
WEBHOOK确认支付HMAC 与金额核对
OUTBOX记录事件同事务写入
WORKER生成电子票队列重试
ON-SITE扫码签到唯一约束

06

数据一致性与安全设计

项目在身份、权限、交易、异步任务和现场设备五个层面设置控制点。高风险路径采用服务器重读、签名校验、哈希存储、时间窗口和幂等约束。

Inventory

库存一致性

余量计算同时扣除已售、有效预占和候补 offer，创建订单时使用行锁与 advisory lock 控制竞争。

capacity − sold − reservations − offers
  • 15 分钟订单预占
  • 状态过期后释放
  • 事务内更新业务事实
Webhook

支付回调防护

支付回调校验 HMAC、时间窗口、金额、币种和外部交易号，重复请求落到相同结果。

HMAC + 5 min + amount + currency + txn id
  • 幂等键
  • 外部交易号唯一
  • 敏感错误收敛
Check-in

现场同步幂等

签到记录由票据和签到清单唯一约束，离线批次同时校验组织、活动、设备、批次与请求体哈希。

org + event + device + batch + body hash
  • 设备令牌哈希
  • 重复签到阻断
  • 100 设备验收场景

关键控制矩阵

风险 控制手段 保护对象 验证关注点

异步消息丢失 事务 Outbox、队列重试、Worker 消费 通知、候补、导出 积压、死信与恢复监控

全球化与多语言路线

项目当前以中文管理体验为主。全球化需要同时处理界面文案、通知模板、时间与货币格式、地址模型、区域支付及数据部署策略。

PHASE 2 · PLANNED

PHASE 3 · PLANNED
